# 서울 한옥 레이어 — 소스·절차·주의

2026-09-27. 목표: 지도 범례의 정비사업 아래 **"한옥 구역 (서울)"** 토글로
한옥보전구역(공식 경계)·한옥 동네 대략 범위·등록한옥을 표시.
빌더: `crawler/scripts/hanok_layer.py`, 변환: `crawler/src/hanok/layers.py`,
웹: `web/src/lib/hanok-layer.ts` + `property-map.tsx`.

운영은 정비사업/소음 레이어와 같다 — 사람이 받은 소스로 로컬 build →
`web/public/hanok/` 커밋 = 배포. 서울 포털(hanok/data.seoul.go.kr)은 자동 수집
대상이 아니다.

## 레이어

| key | 내용 | 소스 | 형식 | 용도 |
|---|---|---|---|---|
| `preservation` | 한옥보전구역 공식 경계 | 서울한옥포털 → 한옥살이 → '한옥수선 및 신축 지원금액' → '한옥보전구역 지정 공고' | PDF(도면·필지 목록) → **QGIS 수작업** GeoJSON | 지원금 1.5배가 걸린 경계 — 정확도 최우선. 유일한 공식 원본 |
| `district` | 지구단위계획구역 중 한옥 밀집 동네 | 열린데이터광장 OA-21161 | SHP, EPSG:5174, cp949 | **배경**(대략 범위)일 뿐. 보전구역보다 넓다 |
| `registry` | 등록한옥 | 열린데이터광장 OA-15415 | CSV (등록번호·주소·대지면적·연면적) | 주소 지오코딩 점 — 경매 물건이 등록한옥인지 판별 |
| (검증 전용) | 한옥비용지원 내역 | OA-15415 연관 데이터 | CSV | 보전구역 폴리곤 교차 검증. **지도에 싣지 않는다** |

`district` 필터 키워드(`DISTRICT_KEYWORDS`): 북촌, 경복궁서측(서촌), 인사동,
돈화문로, 익선, 운현궁, 조계사, 선잠단지, 앵두마을. 구역명 필드명은 배포본마다
달라 `DGM_NM`/`ALIAS`/… 우선, 없으면 모든 문자열 속성을 훑는다.

## 절차

소스 폴더 `HANOK_SRC_DIR` (기본 `~/Downloads/hanok`):

```
preservation.geojson        # 2) 에서 만든 보전구역
district/  또는 district.zip # OA-21161 SHP 그대로
registry.csv                # OA-15415
```

1. **좌표 변환 (5174 → 4326)** — build 가 한다. `redevelopment/proj5174.py`
   (Bessel + 7-파라미터 towgs84 `-115.80,474.99,674.11,1.16,-2.31,-1.63,6.43`).
   towgs84 를 빠뜨리면 수백 m 어긋난다 — 이 경로는 `tests/test_redev_geo.py`
   앵커로 고정돼 있다. 변환 결과가 서울 박스 밖이면 build 가 멈춘다.
2. **보전구역 폴리곤 제작 (QGIS)**
   - 연속지적도(브이월드) 위에 공고 도면/필지 목록을 대조하며 폴리곤을 딴다.
   - 속성: `name`(구역명), **`notice_date`(공고일, YYYY-MM-DD) 필수**, `notice_no`(공고번호, 선택).
     한 공고로 전부 같으면 `build --notice-date 2024-03-05` 로 대신 지정 가능.
   - **EPSG:4326 으로 내보내기**. 5174 로 내보내도 GeoJSON `crs` 에 5174 가
     명시돼 있으면 변환해 주지만, crs 없는 투영좌표는 거부한다.
3. `python scripts/hanok_layer.py build [--notice-date YYYY-MM-DD]`
   - 소스 없는 레이어는 **커밋본 유지** (다른 머신에서 build 해도 안 지워짐).
   - 공고일 누락·좌표계 오류는 전체 중단 (exit 2) — 틀린 경계 배포 방지.
   - registry 는 Kakao 지오코딩(`KAKAO_REST_API_KEY`, 캐시 공유). 서울 밖
     오지오코딩 점은 버린다.
4. **검증**: `python scripts/hanok_layer.py verify --subsidy 지원내역.csv`
   → 지원 점 중 보전구역 안 비율과 밖에 찍힌 좌표. 밖이 많으면 그 주변
   폴리곤을 도면과 다시 대조 (보전구역 밖 한옥 지원일 수도 있음).
5. `web/public/hanok/` 커밋.

## 미구현 — 경매 물건 판정 (다음 단계)

경매 물건 주소 → PNU → 연속지적도 필지 폴리곤 → 보전구역과 공간 조인.
경계에 걸치는 필지는 "확인 필요"로 표시. 보조로 OA-22412(건축인허가
지역지구구역, 인허가 이력 필지만). 현재 레이어는 **표시만** 한다.

## 라이선스·고지 (앱 반영 전 필수 확인)

- 서울한옥포털 콘텐츠 = **공공누리 제4유형(상업적 이용·변경 금지)**. 공고
  PDF 를 가공한 보전구역 폴리곤은 유료 앱·광고가 있으면 **서울시에 이용
  허락을 먼저 문의**. 허락 전에는 `preservation.json` 을 커밋하지 말 것.
- 열린데이터광장 데이터는 데이터셋별 이용조건 확인 (OA-21161·OA-15415).
- 면책 문구 "공간정보는 참고용이며 지원 여부는 서울시 심의로 결정됩니다" 는
  레이어가 켜져 있는 동안 지도 우하단에 고정 + 모든 팝업에 표기
  (`HANOK_DISCLAIMER`).
